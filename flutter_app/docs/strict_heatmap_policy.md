# 肌肉热力图严格复刻政策

本文件是肌肉热力图的强制执行政策，优先级高于一般实现便利性和临时演示需求。执行者、代码审查者和验收者都必须遵守本文件。用户提供的参考图决定视觉目标；本文件把“肌肉分离效果必须真实可审查”定义为阻断式完成条件。

## 1. 硬性结论

最终生产构建**严禁**使用简单多边形、矩形、椭圆、梯形、粗略自由手轮廓、随机色块或其它占位形状，冒充参考图中的肌肉分离效果。也严禁把一张整图 PNG 放在画布上，再叠加若干粗糙热区就声称完成了矢量热力图。

下列结果一律视为未完成，不能通过阶段验收：

- 用少量 `moveTo/lineTo` 点连成的大块几何多边形代替胸、三角肌、腹肌、背阔肌、臀肌、股四头肌等解剖区域。
- 只画一个人体轮廓，再用透明度、渐变或颜色覆盖制造“看起来像”肌肉分区。
- 使用未拆分肌群的通用人体 SVG、贴图或在线图片作为生产人体主体。
- 使用参考 PNG 作为可见生产主体，或把 PNG 的颜色/边界直接当作未审查的 mask。
- 用矩形、圆角矩形、椭圆、胶囊形、线段和简单三角形拼出肌肉区域，且没有真实可审查的解剖路径。
- 用一个合并路径同时代表左右肌群，无法独立命中、独立着色或呈现左右差异。
- 只实现前视或只实现后视，或只实现一张静态图而没有与训练分数绑定的独立区域。
- 将“以后补齐路径”“临时 mock”“开发占位”保留在 release/production 构建中。

即使几何形状在屏幕上接近参考图，只要没有可审查的真实路径、mask、纹理裁切和视觉证据，也不得使用“完全复刻”“已完成”等表述。

## 2. 必须达到的资产粒度

人体必须由可缩放的矢量资产或等价的完整 `CustomPainter` 路径组成。生产渲染至少要分为以下层：

1. 基础人体轮廓、头部、躯干、四肢和关节阴影。
2. 每个肌群的独立解剖路径和独立 mask。
3. 每个肌群的热度填充、中心高光和边缘过渡。
4. 沿肌纤维方向绘制并裁切在对应 mask 内的纹理。
5. 深色轮廓、肌肉间分隔线和必要的遮挡关系。
6. 与肌群路径绑定的目标点、引导线和标签。

前视和后视必须同时存在，并使用稳定的路径 ID。左右侧必须有独立 `regionId`；共享一个 `muscleId` 只表示它们属于同一肌群，不代表可以共用一条不可分割的视觉路径。首个可验收版本至少覆盖以下可独立命中的区域：左右三角肌、左右胸大肌、腹直肌分段、斜方肌、左右背阔肌、左右臀大肌、左右股四头肌、左右腘绳肌以及小腿区域。若资产把同一肌群进一步拆成多个解剖头或分区，必须保留清晰的父子 ID 和左右映射。

每条生产路径必须满足：

- 闭合、无自交、无零面积子路径，填充规则固定且可验证。
- 形状边界对应参考图中的肌肉分离线，而不是只对应外轮廓包围盒。
- 可单独进行 `Path.contains` 命中、热度着色、描边和纹理裁切。
- 纹理不会越过路径边界；`saveLayer`、`clipPath` 或等价 mask 必须有可读实现。
- 静态路径、mask 和标签布局可缓存，运行时只更新分数、颜色和选择态。

推荐使用分层 SVG（每个区域有稳定 `id`）解析为 Flutter 路径，或把同等粒度的路径集中放在独立的 Dart 常量文件。无论采用哪种方式，都必须能在代码审查中定位每个肌群的来源和绘制层级。

## 3. 外部项目和可复用资产优先规则

执行者在自行绘制大量解剖路径前，必须主动搜索可复用的 Flutter package、pub.dev 组件、GitHub 开源项目、可导入 SVG/矢量人体资产和医学/运动开源图谱。搜索不是可选项：它的目的在于减轻开发压力，同时提高路径质量和可维护性。

若发现已有方案同时满足下列条件，应优先适配、封装并嵌入，而不是从零重绘：

- 有前视和后视人体或可可靠补齐两种视图。
- 肌群已按真实解剖边界拆分，路径粒度足以支持本政策第 2 节的区域清单。
- 资源格式适合离线打包（SVG、路径数据或可转换的矢量格式），运行时不依赖远程图片或服务。
- 能为每个区域建立稳定 ID、命中区域、热度填充和纹理 mask。
- Flutter/Dart 版本和 Android 构建链兼容，或改造成本、风险和验证方式可明确说明。
- 许可证允许当前应用的分发方式和预期用途，并能满足署名、NOTICE、源码公开或同类义务。
- 资源来源、版本/commit、修改内容和完整性可以记录并在未来复现。

“优先复用”不等于无条件引入。以下情况必须拒绝该资产或仅作为参考：许可证不明、仅允许个人使用、禁止衍生作品、要求无法履行的署名/网络回传、资产是位图而非可分离矢量、路径粒度不足、来源不可验证，或项目已明显失维护且引入会造成更大风险。

如果外部项目只有部分满足目标，执行者应说明采用范围和缺口，并只复用符合许可证和质量要求的部分。缺失区域可以人工补画，但补画路径必须遵守本文件，不能用占位多边形填洞。若没有合适的现成项目，必须记录已搜索范围和拒绝原因，然后继续制作完整的自有矢量资产，不得以“没有找到”作为降低视觉要求的理由。

## 4. 外部资产审查记录

每个候选项目都要在工程文档中留下可审查记录，至少包括：

| 字段 | 要求 |
| --- | --- |
| 项目/包名 | pub.dev 名称或 GitHub `owner/repo` |
| 来源 | 可访问 URL，必要时记录下载地址 |
| 检索日期 | 使用 `YYYY-MM-DD`，按项目时区记录 |
| 版本 | pub.dev 版本、Git tag 或完整 commit SHA |
| 许可证 | SPDX 标识和仓库中的许可证文件路径 |
| 资产范围 | 前/后视、肌群数量、左右拆分、文件格式 |
| 适配方式 | 直接使用、转换 SVG、提取路径或封装 package |
| 修改记录 | 对原路径、颜色、命名、纹理和布局的改动 |
| 归因义务 | `NOTICE`、应用内致谢、源码公开等要求 |
| 决策 | 采用、部分采用或拒绝，以及具体原因 |
| 风险 | 兼容性、解剖准确性、维护状态、许可证或构建风险 |
| 验证证据 | 文件哈希、截图、Golden Test、路径审计或构建日志 |

建议使用以下模板追加到 `docs/` 的资产清单中：

```text
项目：<名称>
来源：<URL>
检索日期：<YYYY-MM-DD>
版本/commit：<版本或 SHA>
许可证：<SPDX>，许可证文件：<路径>
覆盖范围：<front/back、区域数量、左右拆分>
采用方式：<直接使用/转换/部分采用/拒绝>
修改：<无或具体修改>
归因义务：<具体内容>
决策理由：<为何契合或不契合>
验证：<命令、截图、Golden、哈希或审查记录>
```

不得因为包名含有“muscle”“anatomy”或展示图好看就直接依赖；必须检查实际路径数据和许可证。不得把搜索结果、README 截图或项目演示页面当作产品视觉证据。

## 5. 视觉和结构验收证据

执行者必须提供可复现的证据证明肌肉确实被分离，而不是通过整体图片或粗略形状伪造：

- 前视、后视各一张独立路径资产的审查图，能看到肌群边界、轮廓和纹理裁切。
- 至少 `score=0`、`score=0.5`、`score=1` 三组热度基准截图；热度只改变对应肌群，不覆盖相邻区域。
- 左右侧分别点击/命中测试，证明相邻区域不会误选；选中态有独立描边和光晕。
- 显示/隐藏热力层或调低透明度后的结构截图，证明底层解剖分区真实存在，不是热力颜色制造的假边界。
- 目标窄屏和宽屏尺寸的截图或 Golden Test，证明缩放后路径、标签、引导线和纹理仍对齐。
- 生产构建资源审计，证明参考 PNG 未作为人体主体加载；PNG 只能留作只读视觉回归对照。
- 路径审计表：每个 `pathKey`、`regionId`、`muscleId`、视图、左右侧、包围盒和来源文件均可追溯。
- 外部资产采用时，许可证文件、NOTICE/归因文本和版本锁定记录随工程提交。

视觉验收应以参考图测得的设计坐标、颜色、层级、边界和标签位置为准。只提供“运行起来了”的视频、单张整图截图或主观描述，不足以证明通过。

## 6. 阻断式审查问题

以下任一问题回答为“是”，必须阻断发布并退回实现：

1. 生产人体是否仍由整图 PNG、网络图片或不可分离的通用人体贴图承担主体？
2. 是否有任何主要肌群使用简单多边形、包围盒、椭圆或颜色块作为最终形状？
3. 是否有肌群无法独立命中、独立着色、独立描边或独立裁切纹理？
4. 左右侧是否共用不可区分的路径，导致训练分数或触点无法区分？
5. 是否缺少前视/后视中的真实肌肉边界、肌纤维纹理或遮挡层？
6. 是否没有记录外部项目的来源、版本、许可证和修改内容？
7. 是否用未验证的第三方资源替换了本地离线资产，或让核心热力图依赖网络可用性？
8. 是否没有截图、Golden Test、路径审计或其它可复现的视觉证据？
9. 是否把未完成的占位路径留在 release/production 构建中？
10. 是否在报告中使用“完全复刻”但没有列出已知偏差和未验证项？

## 7. 给执行者的强制指令

在主 Goal、热力图专项提示词和每次阶段恢复提示词中，必须保留或等价表达以下指令：

```text
肌肉热力图是阻断式视觉任务。严禁用简单多边形、矩形、椭圆、粗略色块、通用人体贴图或整图 PNG 冒充肌肉分离效果。最终生产实现必须使用真实可审查的前/后视解剖路径，每个主要肌群具有独立的左右侧 region、mask、热度填充、纹理裁切、描边和命中测试。先主动搜索 pub.dev、GitHub 和可离线打包的矢量资产；若发现符合目标且许可证允许的可复用项目，优先锁定版本并适配，记录 URL、版本/commit、许可证、修改和归因义务。若没有合适项目，记录搜索和拒绝原因后制作完整路径。没有路径审计、许可证记录、目标尺寸截图或 Golden/人工差异证据，不得声称热力图已完成或完全复刻。
```

执行者每次提交热力图相关代码时，都应在阶段报告中回答：本次新增或复用了哪些真实路径？每个路径的来源和许可证是什么？哪些区域仍未达到第 2 节粒度？运行了哪些视觉证据和构建验证？只要仍有占位形状或未验证区域，就必须明确标记为未完成，并继续推进或报告具体阻塞。

## 8. 完成定义

只有同时满足以下条件，才能将肌肉热力图标记为完成：

- 前视和后视均由真实、可缩放、可审查的解剖路径绘制，生产构建不依赖整图 PNG。
- 主要肌群按左右侧独立拆分，具有稳定 ID、mask、热度映射、纹理裁切、描边和命中测试。
- 参考图中的外框、人体层级、热度渐变、肌纤维纹理、标签、引导线和目标点均有实现和位置证据。
- 已主动检查可复用的 package/开源项目；采用的项目有完整许可证与版本记录，拒绝的候选有理由记录。
- 目标窄屏和宽屏截图、Golden Test 或等价人工差异报告均已存档，并写明误差和未验证项。
- `flutter analyze`、相关测试和 Android debug 构建通过；任何环境限制已如实记录。
- 独立审查者对本文件第 6 节的阻断问题全部回答“否”。

未满足任一条件时，交付物只能称为“热力图基线”“矢量迁移中”或“待验收”，不能称为最终实现。
