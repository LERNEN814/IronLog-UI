## 2026-10-04 SVG 分层修复

- 生产层级现在是面板背景 -> 真实前/后视 SVG ColorMapper -> SVG alpha ShaderMask 纹理 -> 选中描边/标签/命中语义。
- `MuscleHeatmapPainter` 的旧 cubic Path 默认不再绘制填充、纹理或轮廓，因此不能遮盖 SVG 的头部、手部、足部和细粒度肌肉路径；它只在选中时绘制独立描边，并继续承担命中测试和语义锚点。
- API 35 新截图：`docs/evidence/android_api35_heatmap_svg_final.png`。截图确认完整头部、手部、足部和躯干可见，胸部训练热度仍映射为红色。
- 标签层已收敛为参考图的主要标注：前视 `Deltoids/Abs/Quadriceps`，后视 `Trapezius/Lats/Glutes/Hamstrings`；其他肌群仍可点击和通过无障碍语义访问。
- 当前仍没有同尺寸、同坐标、同状态的参考面板，因此不生成正式像素/SSIM 通过阈值。

## 2026-10-03 映射审计补充

- 移除了未调用的粗略 `_drawFigure` fallback；生产人体层只保留前后视 SVG 和独立交互 Path，避免静态审查误把简化轮廓当作可交付人体主体。
- `sartoris`、`adductor`、`pectineus`、`gracilis` 和 `iliotibial` 等下肢 SVG ID 现在归入稳定的 `quadriceps` 或 `hamstrings` 热度组；映射由 `MuscleHeatmapColorMapping` 测试锁定。
- API 35 重新安装后的证据为 `docs/evidence/android_api35_mapping_check.png` 和 `android_api35_mapping_check.xml`，确认日期范围按钮、前后视按钮和独立肌群语义仍可见。
- 该补充只证明路径/ID/运行时语义没有回归，不改变自动像素阈值、真机/横屏和设备空范围等未完成状态。

## 可复现的图像基线（2026-10-03）

本轮使用 Python 3.14、Pillow 和 NumPy 对现有文件做了只读统计。统计脚本没有写入生产资源，也没有把整页截图与参考图直接进行 MSE 比较；Android 截图包含系统状态栏、页面标题和底部导航，参考图是 794 x 855 的热力图面板裁剪，二者坐标系不同。

参考图 `assets/reference/muscle_heatmap_reference.png`：

- 尺寸：794 x 855；SHA-256 仍以 `docs/reuse_evaluation.md` 为准。
- 四角中位背景估计为 RGB `(29, 29, 39)`；与该估计相差超过 28 的像素占 34.25%。这个前景比例包含标签、引线和热力图，不能单独解释为人体面积。
- 亮度边缘密度（水平/垂直相邻像素差阈值 24 的平均比例）为 0.0481。
- 以 10 x 10 粗网格统计暖色像素（`R > G + 20` 且 `R > B + 10`），暖色主要集中在网格行 1 至 8、列 1 至 3 和列 7 至 8，符合左右两个人体区域的构图；这只是构图基线，不是肌群分割证明。

本轮新增 `docs/evidence/heatmap_panel_diff.json` 作为诊断基线：按 API 35 UIAutomator 面板边界 `(55,290)-(1025,1614)` 及对应宽屏比例裁剪，再用 Lanczos 对齐到参考图 `794x855`，计算 MAE/RMSE。该裁剪是整页截图中的近似面板边界，参考图和运行面板仍存在视口、状态和构图差异，因此结果不能作为视觉通过阈值；当前 MAE 约 `37.230-42.108`、RMSE 约 `63.114-70.318`，明确保留为未通过/未验收诊断证据。后续若要设置验收阈值，必须先生成同一设备、同一面板边界、同一数据状态的专用面板截图，再独立确定阈值。
