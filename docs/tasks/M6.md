## T6.1 导出 / 导入
- `domain/backup/BackupModels.kt`：`@Serializable` 的 `BackupFile(schemaVersion, appVersion, exportedAt, muscles, exercises, exerciseMuscles, sessions, sessionExercises, sets, bodyWeights)`。
- `data/backup/BackupRepository.kt`：
  - `exportTo(uri: Uri): Result<Int>`（返回记录条数）—— 在 `Dispatchers.IO` 上，一次性事务读全表 → 序列化 → 写入 `ContentResolver.openOutputStream(uri)`。
  - `importFrom(uri: Uri): Result<Unit>` —— 校验 `schemaVersion == 1`（不等则返回失败并说明）→ 在一个事务内清空所有表 → 写入 → 重新导入种子中缺失的内置动作。
  - **导入前必须由 UI 二次确认**（"将覆盖当前所有数据"）。
- UI：`ui/feature/settings/BackupSection.kt` —— 【导出数据】用 `ACTION_CREATE_DOCUMENT`（MIME `application/json`，默认文件名 `IronLog_备份_YYYY-MM-DD.json`）；【导入数据】用 `ACTION_OPEN_DOCUMENT`。
- 测试（Robolectric）：
  - 导出 → 解析回 `BackupFile` → 各表条数与数据库一致。
  - 空数据库导出不崩溃（各表为空数组）。
  - 导入 schemaVersion 不匹配 → 失败且**数据库未被清空**（先用临时表或先校验再清空）。
  - 导入成功 → 数据与导出前一致（往返一致性）。
- 新增依赖（**需在交接报告"待审批"中申请**）：无（用 SAF + kotlinx.serialization 即可）。

## T6.2 自动备份
