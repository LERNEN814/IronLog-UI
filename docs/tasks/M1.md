## T1.4 数据库 v1 + 种子导入

**产出**
- `data/db/entity/`：8 张表的 `@Entity`（`muscle_group`、`exercise`、`exercise_muscle`、`workout_session`、`session_exercise`、`workout_set`、`body_weight` + 必要的索引）。
  - 外键：`session_exercise.session_id → workout_session.id` (CASCADE)、`workout_set.session_exercise_id → session_exercise.id` (CASCADE)。两个 FK 列都要建索引。
  - `body_weight.local_date` 唯一索引。
  - 所有枚举列用 `Int` 且带 `@ColumnInfo(defaultValue = "...")`。
- `data/db/converter/`：领域枚举 ↔ Int 的映射工具（放在 mapper 中即可，不要求 `@TypeConverter`）。
- `data/db/dao/`：`MuscleGroupDao`、`ExerciseDao`、`WorkoutDao`（会话/条目/组的查询）、`BodyWeightDao`。M1 只需要：
  - 插入/查询动作与肌群、统计数量。
  - `getLastSetsForExercise(exerciseId)`：实现 DOMAIN_RULES §3.1 的 SQL 契约。
- `data/db/IronLogDatabase.kt`：`@Database(version = 1, exportSchema = true)`。
- `data/db/Migration.kt`：`val ALL_MIGRATIONS: Array<Migration> = emptyArray()`（M1 为空，保持文件存在以便后续追加）。
- `core/di/DatabaseModule.kt`：provider（`Room.databaseBuilder`，`addMigrations(*ALL_MIGRATIONS)`，**不得**加 `fallbackToDestructiveMigration`）。
- `data/seed/SeedImporter.kt`：读 `assets/seed/seed_v1.json`，写入 `muscle_group` / `exercise` / `exercise_muscle`；已存在的 id 不覆盖（`INSERT OR IGNORE`），幂等；在 `IronLogApp.onCreate` 中通过注入的 `CoroutineScope`（`@ApplicationScope`，`SupervisorJob() + Dispatchers.IO`，在 `AppModule` 中提供）启动导入。
- `app/src/main/assets/seed/seed_v1.json`：由 `seed_muscles_reference.json` 的 muscles 部分 + 你补写的 ≥ 60 个动作组成（格式见 DATA_MODEL §5）。

**测试**
- `data/db/SeedImportTest.kt`（Robolectric + 内存数据库）：导入后 `muscle_group` 恰好 16 条；`exercise` ≥ 60 条；每个动作至少有 1 条 `exercise_muscle` 且 role=PRIMARY；`chest` 的 half life = 48。
- `data/db/LastSetsQueryTest.kt`：覆盖 DOMAIN_RULES §3.1 的 R1–R4。
- `data/db/SchemaTest.kt`：断言 `IronLogDatabase` 的 version == 1 且 `app/schemas/com.ironlog.app.data.db.IronLogDatabase/1.json` 存在。
- JSON 校验测试：`seed_v1.json` 能被 `kotlinx.serialization` 反序列化为种子模型；不存在重复 id；每个 `muscles[].muscle_id` 都存在于 muscles 列表。

**验收**：`--tests "com.ironlog.app.data.*"` 且 `bash scripts/verify.sh` 全绿。
**注意**：schema JSON 必须一起提交。
