## 4. 偏离规格 / 自行解释之处
1. **分享图渲染用自定义 View 而非离屏 Composable + GraphicsLayer**：Robolectric 下 `GraphicsLayer.toImageBitmap()` 不可用（M0 审计预案明确允许此回退）；Composable 侧通过 `AndroidView`（`ShareCard`）展示同一张卡片。
2. **分享入口放在"训练详情页"**（按钮"分享本次训练"），而不是结束后自动弹出：M2 结束后直接回主页，自动弹分享会打断流程；分享数据在 `SessionDetailViewModel` 装配。
3. **分享卡片固定高度 1350px、最多 12 个动作**；部位色条最多 4 个（PRD R-4.2 上限）。
4. **热力图点击后的"最近刺激摘要"简化为 `7 日刺激：N`**（分数），没有单独计算"最近一次刺激时间"。
5. **简化人体图覆盖 14 个肌群**（无 `side_delts` 与 `cardio` 区域）；`cardio` 分数在数据层仍有，只是身体图上没有形状。
6. **Robolectric Canvas 不做像素光栅化**：`ShareCardRendererTest` 只断言位图尺寸与空数据不崩溃；像素内容只能在真机看。
7. **PR 徽标不持久化**：每次 `loadSession()` 从历史+本会话已完成组重新推导（同一算法），所以重进页面仍能看到 🏆，但没有存储位。
8. **`MediaStore` 保存仅 API 29+**：26–28 需要 `WRITE_EXTERNAL_STORAGE(maxSdkVersion=28)`，按指令先停下报告，未写入 Manifest。
9. **`startSessionFromTemplate` 在源会话无条目时仍会创建一个空会话**（规格未定义"空模板"行为）。

## 5. 已知问题 / 技术债
1. **UI 层无自动化测试**：热力图绘制/点击、分享按钮、Snackbar、相册保存与分享面板都只有编译与 `@Preview` 保证。
2. **`MediaStore`/`FileProvider` 路径未在设备上验证**（Robolectric 无法覆盖）。
3. **`HomeViewModel` 每次进入主页都重新计算疲劳度**（`LaunchedEffect(Unit)` + `FatigueRepository.scores`）；数据量大时会有一次全量查询。
4. **`ExerciseHistoryViewModel` 的 PR 与训练页 PR 各有一套推导**（共用 `OneRepMax` 与"严格大于"，但一处按天聚合、一处按组滚动），未来若要统一需抽公共函数。
5. **M2/M3/M4 真机清单仍未填写**，本报告 §7 的 4 项也是空表。
