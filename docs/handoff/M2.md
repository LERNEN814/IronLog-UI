## 4. 偏离规格 / 自行解释之处
1. **训练页单位切换是"本次训练临时显示单位"**：切换只改 UI 文本，不写 DataStore（PRD R-2.7"只改显示，不改存储"），全局默认单位仍以设置为准。
2. **距离字段以米（m）为单位录入**：`distance_m` 存储不变；R-2.9 的"距离（可选）"在 M2 用 "距离(m)" 文本框实现，读取 `distance_unit`（km/mi）的换算留到 M4/M6（设置项已可修改并持久化，但训练页暂不消费）。
3. **时长键盘输入单位是秒**，组行与汇总显示 `mm:ss`（R-2.9 要求显示分:秒；输入口径未规定，取存储单位秒最简单）。
4. **`ExerciseRepository.search(query, filter)` 的 filter 语义改为 `body_region`**（M1 实现曾是 `ExerciseKind.ordinal`）；M2 选择页的按部位筛选需要它，类型筛选不在 M2 UI 中。
5. **预填占位值保存在 ViewModel 内存**（不写库，保证 R-2.4 灰色占位语义）：进程被杀后，未修改的预填组会按"上次数据"重新计算（结果一致）；手动"添加一组"复制的占位值在重启后变为空行（数据不丢，只是需重新输入）。
6. **历史详情用 BottomSheet 展示**（"至少可查看所有组"），未新建详情路由；M4 再做可编辑详情页。
7. **`exerciseCount` 汇总口径**：按 D2，只统计"至少 1 个已完成组"的条目（热身组也算已训练但不算正式组）。
8. **删除组用左滑**（PRD R-2.6），删除/移动动作通过长按条目或 ⋮ 菜单打开（长按区域为整个卡片头部）。
9. **group number 规则**：热身 W、递减 D、力竭 F，只有正式组参与 1,2,3 序号（PRD 仅明确热身不计数，其余取最直观处理）。

## 5. 已知问题 / 技术债
1. **列表页 N+1 查询**：`observeRecentSessionHeaders` 对每个会话逐个查询条目/组/动作/肌群；主页（3 条）无感，历史（最多 50 条）在低端机上可能偏慢。M4/M5 若数据量大再合并查询或加缓存。
2. **UI 无自动化测试**：遵循 AGENTS.md 不写 androidTest；Compose 页面仅靠编译 + `@Preview` + 下方真机清单验证。ViewModel 均有单测。
3. **`onSetCompleted()` 仍是 TODO**（M3 接休息计时器）。
4. **DataStore 无损坏恢复测试**（异常文件、迁移）；当前用默认行为。
5. **`SessionViewModel` 的 `renderEntries` 在单位切换时重算文本**，状态更新频繁时依赖 Flow 收敛；未测极端快速点击。
6. **`WorkoutRepositoryImpl` 中 `startSession` 的竞态修复依赖 Room 事务串行化**（单事务线程）；如果未来配置多线程事务执行器需要复测。
