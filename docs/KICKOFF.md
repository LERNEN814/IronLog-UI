# 启动提示词（Kickoff Prompt）

> 使用方式：把下面 **「=== 提示词开始 ===」到「=== 提示词结束 ===」** 之间的内容整段复制，作为第一条消息发给 Pi Agent。
> 之后每个里程碑结束时，把 `docs/AUDIT.md` 里对应的"审计提示词"发过去。

---

=== 提示词开始 ===

你现在是 **IronLog** 项目的编码代理，工作目录就是本仓库根目录（包含 `AGENTS.md` 的那一层）。

IronLog 是一个**仅 Android、离线优先**的力量训练记录 App。目前处于 Phase 1（训练记录），按里程碑 M1 → M6 推进。项目发起人和审计官由我担任。

## 你的第一步（现在就要做）

1. 完整阅读 `AGENTS.md`（这是你的守则，里面的"红线"违反任何一条都会导致整个里程碑被打回重做）。
2. 阅读 `docs/PROGRESS.md`，确认当前里程碑是 **M1**。
3. 阅读 `docs/tasks/M1.md`（这是你要做的全部工作，共 6 个任务 T1.1–T1.6）。
4. 按需阅读 `docs/ARCHITECTURE.md`（包结构、UI 模式、第 9 节的"本机工具链已知坑"必须遵守）和 `docs/DOMAIN_RULES.md`（每个测试向量都必须写成单元测试）。

## 工作方式

- **一次只做一个任务**，按 T1.1 → T1.6 顺序。
- 每个任务：先写测试（领域逻辑测试先行）→ 写实现 → 跑任务卡里给出的验收命令 → `git commit -m "M1-T1.x: <英文简述>"` → 更新 `docs/PROGRESS.md` → 下一个任务。
- 在 Windows Git Bash 下工作。跑 gradle 之前先 `source scripts/env.sh`。gradle 命令超时请设 **600 秒以上**（首次构建需要 5–10 分钟）。
- 遇到同一个错误连续失败 3 次，就把它记进 `docs/PROGRESS.md` 的"阻塞项"，跳过它去做不依赖它的任务；如果全被卡住就停下来告诉我。
- **不要**自作主张扩大范围：不做 `docs/tasks/M1.md` 之外的任何功能，不添加未批准的依赖，不修改受保护文件（`scripts/verify.sh` 会检测并报 FAIL）。

## M1 的完成标准

`bash scripts/verify.sh` 输出 `VERIFY RESULT: 0 FAIL`。这项检查包括：
- 静态红线检查（受保护文件未被改动、无直接取系统时间、domain 层无 android import、无中文硬编码、无 `@Ignore` 等）；
- `assembleDebug` 编译通过；
- 所有单元测试通过且**零 skipped**；
- `lintDebug` 通过；
- Room schema JSON 已导出并提交。

## M1 完成后

1. 按 `docs/handoff/TEMPLATE.md` 写 `docs/handoff/M1.md`，如实填写（包括没做到的、偏离规格的、需要我审批的）。
2. 更新 `docs/PROGRESS.md`，把 M1 的任务全部标为 `[x]`。
3. **停止工作**，输出一句话：「M1 已完成，请发起审计」，并附上 `scripts/verify.sh` 的最后输出。

**不要**开始 M2。等我的审计结果和下一步指令。

现在开始：先读 `AGENTS.md` 和 `docs/PROGRESS.md`，然后告诉我你打算怎么安排 T1.1，再动手写代码。

=== 提示词结束 ===

## 备注（给项目发起人，不要发给代理）

- 代理可能会想"顺便"把 M2 的界面也做了。它一提交超过 M1 范围的东西，就在审计里指出来，但**不需要**回滚——只要它没引入新依赖、没破坏 M1 的门禁即可，让它在 M2 继续用。
- 如果代理报告某个 gradle 命令"很慢"，这是正常的（首次 5–10 分钟，之后 1–2 分钟）。不要让它为了"提速"改 `gradle.properties`（那是受保护文件，会 FAIL）。
- 如果代理卡在 T1.4（Room/种子导入）超过 3 次尝试，让它先把 T1.1/T1.2/T1.3/T1.5 做完再来处理 T1.4，这几个任务互相独立。
- 每个里程碑结束后，把 `docs/AUDIT.md` 中的对应审计提示词发给它，并把它的回复交给我（审计官）做最终裁定。
