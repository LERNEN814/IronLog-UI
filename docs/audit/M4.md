## 发现的问题
1. **【缺陷·数据污染】已有进行中训练时，"以此为模板开始训练"会把动作追加进当前训练。**
   - `onStartTemplate` 调用的 `startSession()` 在已有进行中会话时会直接返回它的 id（这是 M1 为防双击设计的幂等语义），于是模板里的动作被追加进当前训练，而且 `order_index` 从 0 开始，与已有条目重号。
   - 另外，整个流程分多次写库，不在同一个事务里，中途失败会留下半个会话。
2. **【隐患·将来会崩溃】批量 `IN (:ids)` 没有分块。**
   - minSdk 26：API 26–29 自带的 SQLite 版本低于 3.32，一条语句最多 999 个参数。
   - 日历一次取 500 个会话，条目数会随使用累积（每周 3 练 × 每次 5 个动作，大约 1.3 年就会超过 999），届时日历和历史页会直接崩溃。
   - 这是代理自己在风险 1 中指出的，判断准确。
3. **【记录】死代码**：M2 的只读历史 BottomSheet 路径已不再使用。
4. **【记录】** CalendarViewModel 和 ExerciseHistoryViewModel 没有测试。其中日期分组和 `LocalDate.parse` 这些接线逻辑，至少要有一条测试覆盖。
