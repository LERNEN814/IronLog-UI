## 必须修复
1. **【缺陷·阻断真机验收第 2 项】前后台切换没有接线。** `RestTimer.onForegroundChanged()` 在生产代码中**没有任何调用方**（grep 只找到定义）。`start()` 总是在前台被调用，因此"进行中"通知永远不会出现：按 Home 键后通知栏看不到倒计时，回到前台时也不会取消通知。测试全部使用 `FakeForegroundState` 并直接调用该方法，所以掩盖了这个问题。
2. **【缺陷·阻断真机验收第 3 项】冷进程收到闹钟时静默丢失。** 进程在后台被杀（国产 ROM 在省电或锁屏时很常见）之后，闹钟到点会冷启动进程。`RestAlarmReceiver` 注入的是一个新的 `RestTimerRepository`，其内存中 `sessionId == null`，于是 `onAlarmFired()` 直接 return：
   - 没有"时间到"通知；
   - 2001 进行中通知不会被取消，Chronometer 会一直走到负数；
   - `init { restore() }` 与 `onAlarmFired()` 之间还存在并发竞态。

   代理把这种情况当作"无会话 → no-op"的预期行为写进了偏离第 5 条，但它恰恰是后台计时最关键的路径。规格 §7 只写了 MainActivity 恢复，没有覆盖 Receiver 冷启动，这是**审计官的规格漏洞**，已通过 D5 补上。
